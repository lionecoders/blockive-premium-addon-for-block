# QA Testing — P1 Findings — 2026-08-22

Stage 2 (QA Testing) for the 12 P1 code-review findings. Live-tested in the WordPress editor and frontend on `blockive-git.local`, test page: **QA Sweep - P1 Blocks** (`/qa-sweep-p1-blocks/`, post ID 398). Blocks covered: Accordion, Contact Form 7, Countdown Timer, Image Box, Lottie, Post Grid, Pricing Table, Team.

## Confirmed as reported

- **A-1 (Accordion keyboard/ARIA)** — Confirmed via DOM inspection: `.bpafb-accordion-header` has `tabIndex: -1` and no `role`. Not reachable by keyboard at all.
- **A-5 (Contact Form 7 shortcode injection)** — Confirmed live. Setting the Form ID field to `1"][gallery]` caused WordPress to parse it as two separate shortcodes; the frontend rendered "Error: Contact form not found." followed by the leftover output of the injected `[gallery]` shortcode. Real injection, not just a theoretical parsing concern.
- **A-7 (Countdown Timer crash)** — Confirmed exactly as described. With a past target date, the frontend throws `ReferenceError: Cannot access 'u' before initialization` inside the `NodeList.forEach` callback in `view.js`, matching the predicted temporal-dead-zone bug.
- **B-7 (Image Box RichText mismatch)** — Confirmed live. Bolding "Read More" in the editor produces literal visible text `<strong>Read More</strong>` on the frontend (not bold) — `hasStrong: false` on the rendered anchor.
- **C-12 (Post Grid "By Author" placeholder)** — Confirmed in the editor: the block preview shows the literal string "By Author" for every post regardless of actual author.
- **C-14 (Pricing Table mutation bug)** — Confirmed live and worse than the write-up suggested: clicking "Add Feature" on a freshly-inserted, unedited table added the feature with no crash, but **Ctrl+Z (Undo) did not remove it after two attempts**. This is a real, reproducible undo/redo break, not just a theoretical risk.

## Revised after live testing

- **C-2 (Lottie unpkg script) — downgrade from P1 to P3.** Live network monitoring on the frontend shows the `unpkg.com/@dotlottie/player-web@latest` script is **never actually requested**. Reading the built `view.js` shows why: the guard `!document.querySelector('script[src*="lottie"]')` is meant to detect whether the player is already loaded, but it also matches the view script's own `<script src=".../lottie/view.js">` tag (the file's own path contains "lottie"). The guard is always true-blocking, so the injection is dead code that can never execute in practice. No supply-chain/privacy exposure actually exists today — but the code is genuinely dead and misleading and should still be removed. Recommend re-filing as P3 cleanup rather than P1 security finding.

## Could not verify — needs follow-up

- **D-1 / C-15 (`border: none !important` defeats shared container Border control)** — I was unable to locate a structured "Border" control (width/style/color) in the live inspector for either the Accordion or Team block, despite `bpafbContainerBorderWidth`/`bpafbContainerBorderColor` etc. being registered in `block.json`. The only border-adjacent controls found were: a per-image "Image Border Width" slider (Team's Styles tab, unrelated to the container), and a freeform "Additional CSS" textarea (Team's Advanced panel — see below). Setting `border: 6px dashed #00ff00 !important` via that Additional CSS field did visibly override the block's `border: none !important` reset, confirming the CSS cascade mechanics described in the finding are real — but I could not confirm the finding's original premise (a *structured* Border control being silently defeated) because I couldn't find that control in this build. **Needs a follow-up pass**: either the control is hidden behind something not yet discovered, it was removed/never wired for these two blocks specifically, or the code reviewer inferred its existence from the registered attributes without confirming it renders. Do not fix this as originally scoped without re-confirming the actual control location first.

## New observation (not in original backlog)

- **Team block's "Advanced" panel has a working "Additional CSS" freeform textarea** with helper text ("Add your own CSS to customize the appearance of the Blockive Team block...") that is **not documented anywhere in the B-10 finding** (which claimed AdvancedTab has no Custom CSS UI at all, based on reviewing faq/funfact/heading/icon-box/image-accordion/image-box). This suggests either: (a) Team implements its own separate Advanced-panel injection independent of the shared `AdvancedTab` component, so B-10 may only apply to the six blocks actually reviewed rather than "~70 blocks" as scoped, or (b) B-10's reviewer missed a native `InspectorAdvancedControls` slot-fill mechanism that other blocks also have. **Needs a quick recheck on one of the B-10 blocks (e.g. FAQ) before fixing B-10** — the fix might already partially exist, or the actual gap might be narrower/wider than reported.
- No other unexpected console errors were observed on the test page beyond the confirmed Countdown Timer crash.
