## Root Cause & Fix Summary

- **A-1**: Header `<div>` had `onClick` only. Added `role="button"`, `tabIndex`, `aria-expanded`, `aria-controls`/matching `id`, and an `onKeyDown` (Enter/Space) handler across editor, save, and frontend view script; frontend script now also keeps `aria-expanded` in sync on toggle.
- **A-5**: `formId` was interpolated into a shortcode string unsanitized. Now stripped to digits-only both on input (`edit.js`) and defensively again at render time (`save.js`), so already-saved bad values self-heal on next save.
- **A-7**: `let interval` was declared after the first synchronous call to `updateTimer()`, which reads `interval` in its early-return branch — a temporal-dead-zone bug that only manifests when the target date has already passed. Moved the `let interval;` declaration above the first call.
- **B-7**: `linkText` is a RichText-driven field (supports bold/italic) but was rendered in `save()` as a raw JSX text node, HTML-escaping any formatting instead of rendering it. Switched to `<RichText.Content>`, matching how `title`/`description` are already handled.
- **C-12**: Editor preview hardcoded the string "By Author" instead of reading the real name from the already-fetched `_embed` REST data. Now reads `post._embedded.author[0].name`, matching the PHP frontend's `get_the_author()` output format exactly.
- **C-14**: Mutated `newTables[tableIndex].features` directly instead of replacing `newTables[tableIndex]` with a new object — the same anti-pattern already fixed in `updateFeature`. Applied the identical immutable-spread pattern.
- **D-1 / C-15**: A defensive `border: none !important;` reset on the block wrapper silently overrode the inline styles injected by the shared Advanced-Tab Border control. Removed the reset from the wrapper selector on both blocks (left an unrelated inner-grid selector on Team untouched).
- **E-1**: `bpafb_inject_styles()` used a regex that assumes the block's rendered HTML begins with its wrapper's opening tag. Any block emitting a local `<style>` tag first (for hover-color CSS) had its container styling injected into the `<style>` tag instead. Added a pre-pass that skips past any leading `<style>...</style>` blocks before locating the wrapper tag, then adjusts the replacement offset accordingly.
- **E-2**: `bpafbUid` was only generated when falsy, so a duplicated block (which clones attributes verbatim) kept the original's uid, colliding on the same CSS-scoping class. Added a module-level `Set` of claimed uids; on mount, a block whose uid is already claimed (or missing) gets a fresh one.
- **E-3**: Read and filtered post content without checking password protection, unlike core's `core/post-content` block. Added a `post_password_required()` guard that renders `get_the_password_form()` instead of the content when applicable.

## Backward Compatibility

- All changes are additive (new attributes/handlers) or corrective (fixing logic that was already broken) — no existing attribute, setting, or control was removed or renamed.
- Static blocks whose `save()` output changed (Accordion, Contact Form 7, Image Box, Pricing Table) will show a one-time "Block contains unexpected or invalid content" notice in the editor for already-published posts using them, resolved via the standard "Attempt Recovery" action — no data loss, since recovery re-serializes from the block's existing attributes using the corrected `save()`.
- A-5 and B-7 specifically: previously-saved bad data (an already-injected `formId` or an already-double-escaped `linkText`) is not retroactively cleaned by the code fix alone — it self-heals the next time the affected post is opened and re-saved in the editor.
